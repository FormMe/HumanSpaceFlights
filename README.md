# Human Space Flights — "Astronet" project

Авторы: **Ilya Ovchinnikov** и **Yana Dolzhanskaya**.

Интерактивная визуализация всех пилотируемых космических полётов (с 1961 года) и их участников:
гистограмма запусков по годам, параллельные координаты, список миссий/астронавтов,
граф связей «миссия — астронавт» и карточка с подробностями.

Открыть: `index.html` (нужен любой статический сервер, например `python3 -m http.server`).

## Данные

| Файл | Что это |
| --- | --- |
| `data/missions.csv` | миссии (одна строка = группа экипажа с общим кораблём возвращения), **генерируется** |
| `data/all_astronauts.csv` | астронавты всех стран, **генерируется** |
| `data/meta.json` | дата сборки и счётчики, **генерируется** |
| `data/source/missions_legacy.csv` | исходные вручную собранные миссии 1961–2017 (оригинал проекта) |
| `data/source/astronauts_legacy.csv` | исходные вручную собранные астронавты США и СССР/России |
| `data/source/overrides.csv` | ручные исправления (см. ниже) |
| `data/raw/*.json` | «сырой» снимок Wikidata и Википедии, из которого собираются CSV |

Старые CSV (`EVA.csv`, `astronauts_nasa.csv`, `astronauts_rus.csv`, `suborbital.csv`, `planets.csv`)
приложением не используются и оставлены для истории.

### Как обновляются данные

Пайплайн состоит из трёх шагов:

```bash
pip install -r scripts/requirements.txt
python scripts/fetch_data.py   # 1. скачать Wikidata + Википедию в data/raw/ (нужен интернет)
python scripts/build_data.py   # 2. собрать data/*.csv из data/raw/ (работает офлайн)
python scripts/fetch_photos.py # 3. скачать фото и эмблемы в data/photos/ (нужен интернет)
```

1. **`fetch_data.py`** запрашивает Wikidata (SPARQL) — все люди со свойством «миссия астронавта» (P450),
   все миссии с «членом экипажа» (P1029) и все пилотируемые полёты с 2017 года, — а затем Википедию:
   инфобоксы статей о миссиях (стартовавший / вернувшийся экипаж, даты), инфобоксы статей об астронавтах
   (выходы в открытый космос, время в космосе, год отбора, статус) и вступления статей о миссиях
   (из них берётся краткое описание). Если число людей, миссий или связей упало больше чем на 10 %
   по сравнению с прошлым снимком (`data/raw/meta.json`), скрипт завершается с ошибкой и не
   перезаписывает `data/raw/` — так сбой источника не удалит данные с сайта.
2. **`build_data.py`** берёт исходные курированные данные до 2017 года и дополняет их:
   * всеми орбитальными пилотируемыми полётами после последней миссии в исходных данных
     (суборбитальные полёты New Shepard / Virgin Galactic исключены, как и в оригинале);
   * карточками астронавтов всех стран (Китай, Япония, Европа, Канада, Индия, ОАЭ, частные астронавты…),
     которых раньше не было;
   * новыми полётами, статусом, датой смерти и временем в космосе уже известных астронавтов;
   * экипажами, которые улетели на одном корабле, а вернулись на другом
     (Soyuz MS-22 → MS-23, Boeing Starliner → Crew-9, Shenzhou 20 → 21 и т. п.).

### Откуда берутся данные об астронавтах (методика)

Для каждого человека данные собираются из нескольких источников по порядку;
следующий источник используется, только если предыдущий не дал значения.

| Поле | 1-й источник | 2-й источник | 3-й источник |
| --- | --- | --- | --- |
| Список людей и их полёты | экипажи из инфобоксов статей о миссиях (`crew_members`, `crew_launching`, `crew_landing`) | Wikidata: P450 «миссия астронавта», P1029 «член экипажа» | исходный CSV проекта |
| Имя | написание из исходного CSV (чтобы не ломать связи) | метка Wikidata (`en`, иначе `mul`) | заголовок статьи |
| Дата и место рождения, смерть, пол | Wikidata P569, P19, P570, P21 | инфобокс Википедии (пол — по местоимениям во вступлении) | исходный CSV |
| Гражданство | Wikidata P27 (+ код страны P297) | агентство из инфобокса (NASA → США и т. п.) | исходный CSV |
| Время в космосе | инфобокс `time_in_space` | Wikidata P2873 | сумма длительностей полётов в наборе данных |
| Выходы в открытый космос (число, часы) | инфобокс `total_evas`, `total_eva_time` | исходный CSV | — |
| Год отбора, статус, образование, звание | инфобокс `selection`, `status` / `retired`, `education`, `rank` | Wikidata P69, P410, P241 | исходный CSV |

Как связываются записи одного человека:

1. по общим миссиям: человек из Wikidata сопоставляется с именем из экипажа той же миссии
   в исходном CSV (сравнение фамилии, инициалов, транслитераций);
2. по заголовку статьи: каждое имя из исходного CSV ищется в Википедии
   (`Имя`, `Имя (astronaut)`, `Имя (cosmonaut)`), найденный человек принимается,
   только если это действительно космонавт (описание, полёты или та же дата рождения) —
   иначе можно получить однофамильца;
3. по имени и дате рождения (Serena Auñón = Serena Auñón-Chancellor).
4. по экипажам: если написание из исходного CSV не совпало ни с кем, из экипажей его миссий
   в Wikidata вычитаются уже найденные люди — обычно остаётся ровно один. Один элемент Wikidata
   соответствует одной карточке: другое написание того же человека в экипаже
   («Albert Sacco» при карточке «Albert Sacco Jr.») становится псевдонимом этой карточки.

Проблемы, которые встретились и как они решены:

* **Wikidata Query Service не отдаёт часть элементов.** Wikidata убирает английские
  метки, совпадающие с мультиязычной меткой `mul`, — у Christina Koch, Jared Isaacman,
  Franco Malerba, SpaceX Crew-1 нет метки `en`. Запросы берут `en`, иначе `mul`;
  для пустых ответов есть запасной путь через API `wbgetentities`, а затем —
  сборка записи прямо из статьи Википедии.
* **Вложенные инфобоксы.** У многих людей статья начинается с `{{Infobox person}}`,
  а данные о полётах лежат во вложенном `{{Infobox astronaut|embed=yes}}` — читаются все.
* **Экипаж улетел на одном корабле, а вернулся на другом.** Берётся из полей
  `crew_launching` / `crew_landing` инфобоксов миссий.
* **Даты с точностью до года или месяца** в Wikidata (`2027-01-01` у планируемого полёта) не используются:
  точность сохраняется в снимке (`2027-01-01T00:00:00Z/9`), берётся дата из инфобокса. Даты из инфобокса
  с пометками *planned*, *NET*, *scheduled*, *TBD* тоже не считаются датами — планируемая миссия
  не превращается в состоявшуюся.
* **Даты рождения и смерти**: дата Wikidata с точностью до дня заменяет дату исходного CSV,
  если отличается от неё (в исходных данных были опечатки и перепутанные день и месяц);
  все такие исправления перечислены в `data/audit.json` → `dates_corrected`.
* **Ошибки и разные написания в исходных CSV** (Pawelzyk, Garriot, «Andrew S.W. Thomas» /
  «Andrew S. W. Thomas») исправлены или сведены к одному написанию.

### Аудит

После каждой сборки `data/audit.json` показывает, что ещё не найдено:
члены экипажей без карточки, пустые поля по каждому астронавту, миссии без описания
и подозрительные записи (возраст на момент полёта вне 20–80 лет, смерть раньше полёта —
так обычно проявляется перепутанный однофамилец), экипажи исходных миссий, которые в Wikidata
другие (`legacy_crews_differ_from_wikidata`), исправленные даты (`dates_corrected`) и элементы Wikidata,
попавшие в несколько карточек (`qid_used_by_several_records`, должно быть пусто). `data/raw/diagnostics.json` хранит
элементы, по которым Wikidata ничего не вернула. Колонка `Source` в `all_astronauts.csv`
говорит, откуда запись: `legacy`, `legacy + Wikidata/Wikipedia` или `Wikidata/Wikipedia`.

Оставшиеся пустые поля — пробелы самих источников: у космических туристов и
специалистов по полезной нагрузке нет «года отбора», у части советских и китайских
космонавтов в Википедии не указано образование.

### Фотографии, эмблемы, подробности

* **Портреты астронавтов** — главное изображение статьи о человеке в Википедии.
* **Миссии** — отдельно фото из инфобокса статьи (`image`: запуск, экипаж, корабль)
  и эмблема (`insignia`).
* Берутся **только свободные файлы** — по списку лицензий: public domain / PD-*, CC0, CC BY и CC BY-SA
  (любые версии), FAL, «No restrictions», GODL-India, «Attribution». Несвободные (fair use) Википедия
  может использовать сама, а этот сайт — нет; файл с пустой или неизвестной лицензией тоже пропускается
  (берётся следующий источник). У каждой картинки в карточке указаны автор (для CC BY без автора —
  поле Credit) и лицензия со ссылкой на страницу файла на Wikimedia Commons.
* `fetch_photos.py` скачивает картинки один раз (повторные запуски качают только новое или
  изменённое), уменьшает до WebP примерно до двойного размера показа на телефоне и ретина-экране
  (фото миссий до 800 px, портреты до 480 px, эмблемы до 320 px, плюс крошечные копии 112 px
  для аватарок в списке экипажа и подсказок графа) и раскладывает по пачкам
  `data/photos/pack-*.json` (фото миссий — 128 пачек, портреты — 16, эмблемы — 8, аватарки — 4;
  см. `PACKS` в `fetch_photos.py`). Пачки пишутся в новую папку и подменяют старую целиком;
  после 25 неудачных загрузок подряд скрипт перестаёт качать и оставляет прежние картинки.
  Страница загружает пачку, только когда показывает фото из неё. Там, где хостинг позволяет,
  карточка подгружает оригинал с Wikimedia в высоком разрешении.
* Миссии и люди берутся из Wikidata через обычный API (`wbgetentities`): сервис SPARQL-запросов
  бывает перегружен (429, таймауты), а API отдаёт по 50 записей за запрос стабильно.
* Ещё из инфобоксов и статей: ракета, корабль, места старта и посадки, позывной, оператор,
  описание миссии, агентство и краткая биография астронавта, ссылка на статью.

### Автоматическое обновление

Workflow `.github/workflows/update-data.yml` запускает все три шага в GitHub Actions
**каждый понедельник** (а также вручную — *Actions → Update spaceflight data → Run workflow* —
и при изменении скриптов) и коммитит обновлённые данные в репозиторий. Если не скачались фото,
CSV всё равно коммитятся; запуск, в котором изменились только отметки времени в `meta.json`,
ничего не коммитит. Новый запуск ждёт окончания предыдущего, а не отменяет его.
Расписание GitHub выполняет только в ветке по умолчанию (`master`).

### Ручные исправления

Если в Wikidata/Википедии что-то записано неверно, это правится в `data/source/overrides.csv`,
а не в сгенерированных CSV (их перезапишет следующая сборка):

```csv
mission,member,field,value
Soyuz MS-23,*,skip,
Some Mission,Jane Doe,return_mission,Other Mission
Some Mission,Jane Doe,return_date,2025-03-18
Some Mission,*,habitation,ISS
Some Mission,John Doe,remove,
Some Mission,John Doe,add,
```

* `skip` — не считать запуск пилотируемым;
* `return_mission` / `return_date` — на чём и когда вернулся член экипажа;
* `habitation`, `country`, `summary`, `fatality`, `sub_orbital` — поля миссии (`member` = `*`);
* `remove` / `add` — убрать человека из стартового экипажа или добавить его.

Строки, начинающиеся с `#`, считаются комментариями.
